## Description

Implement the v2 protocol of docs `ns/quick-v2.md` as crate `ns-wire`,
replacing `quick-wire` with no v1 compatibility, with a specification-to-code
table (migration milestone M1).

Acceptance: the table covers every referenced section; the §2.3 examples and
the independent vectors pass.

## Delivered

Crate `crates/ns-wire`, a pure library (no I/O, clock or randomness; callers
pass `now`, keys and nonces):

- Derivations: `NodeId`, `AddressGroup` (`N6` / `N4`), `check_address_conflict`,
  `Lan6Prefix`, alias candidates (`AliasPool`, `alias_candidate`,
  `select_alias`).
- Node records: `NodeRecord` (sign, canonical decode, strict verify, expiry and
  re-sign checks), `next_issued_at`, the §3.3 ordering state `RecordMarks` and
  `RecordDecision`.
- Relay packets v2: `RelayHeader`, `RelayPacket` and the eight bodies,
  `Register` signing, REGISTER admission (`RegisterCandidate`,
  `check_register`), `derive_session_key`, control and reply MACs,
  `accept_relayed_data`, the budget defaults.
- Region member protocol v2: `RegionFrame` for types 1-9 with the envelope
  extension point for the reserved types 10-12, `check_region_channel`,
  `join_region_marks`, snapshot chunking and sequence checks.
- In-tunnel control: `ControlMessage`, `Ack`, `select_endpoints`,
  `accept_endpoints`, `next_endpoint_revision`, `receive_record`,
  `ProbeAttempt::correlate`.
- `RelayId` (canonical `host:port` relay identifiers).

Coverage, out-of-scope owners and the resolved spec questions:
[ns-wire spec coverage](../spec-coverage/ns-wire.md). L1 reviews before the
merge to `next`.
