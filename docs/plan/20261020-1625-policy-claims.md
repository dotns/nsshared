# Policy and claim canonical values

- **status**: implementing
- **createdAt**: 2026-10-20 16:25
- **approvedAt**: 2026-10-20 16:25

## Investigation

The existing account module supplies strict canonical CBOR, Payer, NodeL3Authority
and domain-separated BootstrapEnvelope. Gateway policy compilation and credential
verification consume subject names, bindings, ordered admin scopes, signed URL
request inputs and signed subject-header configuration. Human tokens currently
have no admin-scope producer. Diagnostic policy-version is not policy authority.

## Proposal

Specify bounded pure subject, binding, policy, admin-claim and signed-request
values. Reuse Payer for binary users, full Node identities, M6 ServiceRef where
service-scoped values occur, and BootstrapEnvelope for signed account requests.
Keep signed URL canonical text deterministic and secret-free. Add independent
Python vectors before Rust codecs and consumer assertions. No new publication
kind, evaluator, credential verifier, runtime, key fetch or I/O is included.

## Carriers and risks

Node L3 remains NodeL3Authority. Public-edge values are embedded by family 7.
Admin claims travel inside authenticated admin tokens. Unplaced aggregate policy
and legacy metadata remain explicit open carrier items. Unknown scope, malformed
subject, cross-realm binding and noncanonical bytes refuse. External JWT/key and
material custody remain separate contracts. A decoded value alone grants nothing.

## Verification

Run policy_claim_vectors against independent accepted/refused bytes, all scope
ordering pairs, signed-request domain separation and signed URL canonical input
vectors. Run format/lint before the complete repository self-check.

## Result

Delivered pure subjects, bindings, ordered admin scopes/claims, policy values,
public-edge JWT/header policy values and signed-request canonical input. Account
signing input retains existing envelope domains and bytes. No publication kind,
Node L3 duplicate, runtime, key lookup or evaluator was introduced.

Independent producer/consumer agreement covers 81 cases and four focused tests.
The complete self-check passes 438 tests with zero skipped, one documentation
test, documentation generation and every static/API check. Open carriers and
producer deltas are recorded in the specification and review request.

## Exact JWT strings

Claim names and values are data used by exact JSON property lookup and string
equality. Preserve their original UTF-8 bytes, including whitespace, controls,
empty strings, case and Unicode normalization form, within 256 bytes per field.
Missing fields, non-text fields, invalid UTF-8, oversize values and noncanonical
CBOR remain refusals. Keep the label validator unchanged for references, subjects,
headers, destination tokens and credential scopes. Add independent vectors for
both fields and retain the exact department-value regression before the fix.
