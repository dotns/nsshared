# Relay-addressed quick pairing

## Context

Existing Keynet CLI supports guided invite/pair and owns durable identity and
peer admission through authenticated local IPC. NSGW has bounded TLS WebSocket
and UDP carriers but no short-code rendezvous. Three built-in relay authorities
exist; ten or thirty relays are design capacity, not deployed inventory.

## Proposal

- Replace the public pairing workflow with quick invite/join; keep one runtime.
- Share the short-code, immutable relay directory and pairing protocol contracts.
- Authenticate session participants with their existing identity, bind ephemeral
  encryption keys to the session, and relay only encrypted recipient-bound tokens.
- Use explicit confirmation on both terminals, with clear permission, waiting,
  cancellation and completion messages. No blanket automatic peer approval.
- Allocate codes atomically per relay. Bound lifetime, request count, message size
  and rate. Expire idle/abandoned entries and erase completed/cancelled secrets.
- Keep a finite recovery window for the same approved participant after uncertain
  transport completion. Never reset identity or existing peers on pairing errors.
- Custom relay handoffs include their authority; never infer it or trust a new CA.

## Verification

Parser and directory uniqueness; signature/session/recipient binding; collisions;
concurrent joins; cancellation/expiry/cleanup; malformed and replayed inputs;
rate/capacity bounds; transport retry and restart; terminal/JSON contracts;
cross-repository real TLS pairing; existing account and Keynet regressions.

## Risks

The prefix is public and contributes no secret entropy. Eight digits alone are
not authorization. Peer confirmation must verify identity, not just device name.
The pairing service cannot grant network access. Directory IDs cannot be reused
for a different operator. Multiple independent state writers behind one ID are
unsupported without shared consistency.

## Scope

ns-shared pairing contracts, nsgw temporary broker/carrier, ns CLI and owner IPC,
focused tests and user documentation. No address/DNS or account-mode redesign.
No production deployment or release in this task without explicit authorization.
