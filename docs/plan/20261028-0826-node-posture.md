# Shared Node posture contract

- **status**: completed
- **createdAt**: 2026-10-28 08:26
- **approvedAt**: 2026-10-28 08:26
- **relatedTask**: 20261028-0826-node-posture

## Context

Node heartbeat and disconnect already share runtime fencing and persisted membership envelope validation. The platform collector supplies strings, a disk-encryption enum, uptime and IP literals; the posture store replaces the snapshot and supplies its receive time. There is no shared posture operation.

## Proposal

Add `node.posture` with a versioned request containing membership, runtime fence, request id and an eight-field snapshot. Bound each descriptive UTF-8 string at 1024 bytes and local IPs at 256 entries of at most 45 bytes. Preserve supplied IP spelling and order; validate literals. Use the three existing disk-encryption values. A four-field receipt echoes membership, fence and request id. Reuse persisted-context validation. Add independent Python vectors and typed refusal tests.

## Risks

A receipt correlates only while the sender retains a unique request id for each exact snapshot. Runtime freshness and durable store effects remain consumer responsibilities. All additions stay behind unstable-account.

## Scope

Control report modules, account tests and vectors, vector producer registration and the account control specification.

## Alternatives

Embedding posture in heartbeat would couple independent collection cadence to liveness and is excluded.
