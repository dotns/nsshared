## Context

`ReportContent` in `crates/nsshared-control/src/service/contract.rs` contains scope, strict mode and declarations. Its canonical bytes determine the report digest. `ReportReplace` carries those bytes and `PendingRequest` correlation already compares the accepted revision and digest within the exact runtime context.

The existing `EdgeServiceMetadata` preserves a declaration reference, capabilities and policy labels. `EdgeExitProfile` preserves a reference, selection, enabled intent, capabilities and policy labels. Neither the existing shared Exit profile nor the gateway's local Exit configuration defines a separate binding field.

## Proposal

Extend canonical report content with bounded metadata and explicit CIDR profiles. Exit bindings are profile references within enclosing report scope; metadata references must name declarations in the same report. Preserve existing declaration encodings and empty-extension report bytes. Cover all extension fields with the acknowledged digest and independent positive and negative vectors.

## Risks

Adding fields to the public, exhaustively constructible `ReportContent` struct would break Rust callers even if legacy wire bytes remained unchanged. Preserve both legacy report structs exactly and add complete-floor adapters. A nonempty floor requires the explicit versioned decoder; legacy decoders fail closed. Pure codecs cannot establish current custody without independently persisted consumer state.

## Scope

Service report types, codecs, facade, correlation tests, independent vectors and protocol documentation. Public exports include the floor adapters. Manifests and versions remain unchanged.

## Alternatives

A separately versioned content type can retain the old construction API but requires a specified integration into the existing M6 report carrier. It must not introduce another floor operation.

## Annotations

Initial investigation stopped before implementation because the binding definition and API integration scope were unresolved. The resolved design below supplies those details.

## Resolved design

An Exit binding is its profile reference within the publisher/NSD/Network report scope. Reuse the existing profile shape with explicit CIDRs only. Default selection is refused. Keep `ReportContent` and `ReportReplace` unchanged and add `FloorReportReplace` as the complete-body adapter; `FloorReportMessage` adapts the existing envelope without extending the exhaustive legacy message enum. Nonempty extensions use explicit floor version 1 and a separate digest domain. Empty extensions retain legacy bytes. This is an additive public API; no manifests or versions change. New typed decoding is required for nonempty floors, preventing legacy consumers from discarding fields.

Compatibility verification rejected a defaulted generic parameter in the legacy facade structural surface. The final design preserves that exact structure and exposes the versioned body only through additive types. Existing error discriminants are preserved by appending new variants.
