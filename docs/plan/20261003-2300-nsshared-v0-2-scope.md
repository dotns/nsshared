## Context

The owner defined nsshared as the generic layer only: no application
implementations and no overall architecture definitions, so that application
and component changes do not force nsshared releases. The rendezvous service
is application-neutral and must not carry the Quick name. Pairing and file
transfer become applications of an ns app channel (docs `ns/app-channel.md`).

## Proposal

1. Docs first (docs commit `8ec71f3`): add the ns app channel, rename the
   rendezvous service to `/rendezvous/v1`, narrow the nsshared scope page.
2. Merge `nsshared-wire` and `nsshared-rendezvous` into `nsshared-proto`.
3. Remove the pairing payloads, the in-tunnel control channel, IPv4 aliases,
   `lan6` and the telemetry labels; ns takes them over.
4. Rename the rendezvous constants; regenerate the vectors.
5. Add shared encodings (`nsshared_proto::encoding`).
6. Release `v0.2.0`.

## Risks

- Breaking for ns; ns is pinned to an older commit and moves deliberately.
