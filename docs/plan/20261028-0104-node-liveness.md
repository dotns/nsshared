# Ordinary Node liveness

- **status**: completed

- **createdAt**: 2026-10-28 01:04
- **approvedAt**: 2026-10-28 01:04

## Context

Gateway heartbeat observations carry no membership or runtime fence. Report envelope validation has no trusted membership context. Membership identifiers are provisioned IDs, not signing keys.

## Proposal

Add ordinary Node heartbeat and disconnect payloads, a bounded runtime fence, and a trusted validation context containing accepted membership, enrolled Node identity and NSD authority identity. Preserve existing gateway forms and other operation validation. Add independent Python vectors and Rust refusal and correlation tests.

## Risks

Scope comparisons cannot prove runtime freshness. Consumers must compare the fence against persisted current runtime and commit effects before returning receipts.

## Scope

Account control reports, independent vectors, account tests and the control specification; all new APIs remain behind unstable-account.

## Alternatives

Embedding identity keys in payloads is unnecessary: trusted consumer state supplies identities. Provisioned IDs must never be interpreted as keys.
