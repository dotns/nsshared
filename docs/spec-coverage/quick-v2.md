# quick-v2 spec coverage

Specification-to-code table for the NS protocol v2 wire layer: `nsshared-identity`,
`nsshared-relay`, `nsshared-codec` and the Node-control codec of `nsshared-control`
(re-exported at their 0.6 paths by `nsshared-proto`).

## Notes

- **Docs pin.** Every reference is to docs commit `27a794d` (re-pinned on
  2026-10-11 from `957de97a79f7`); line ranges are those of that commit. Read a section with
  `git -C <docs checkout> show 27a794d:website/src/content/docs/<path>`.
- **Paths.** Code and test paths are relative to the repository root.
  `file.rs::name` names an item or a test function.
- **v1 references.** `ns/quick-protocol.md` (v1) sections are covered only as
  quick-v2 substitutes them: KeyBinding becomes NodeRecord, `(network_id, I)`
  becomes `I`, the `keynet/*` values become `ns/*`, INTRO / INTRO_ACK, BINDING,
  REVOCATION, NAME, `revoked_through` and the v1 QUICK region frames are gone.
- **Status values.** `implemented`; `out of scope: <owner>` for behaviour this
  pure library (no I/O, timers, persistence or state machines) leaves to a
  caller; `deferred: <reason>`. Owners: **nsgw relay**,
  **relay** (the region member protocol, removed on 2026-10-03 because only
  relay instances encode it; last in tag `v0.1.0`),
  **ns node** (the overlay core and the nsplane engine),
  **nsshared-rendezvous** (see [rendezvous spec coverage](rendezvous.md)).
- **Vectors.** The vector test modules consume the fixtures under
  `crates/<crate>/tests/vectors` that `tools/vectors` derives from the spec text
  without calling the crates; see the Vectors section of
  [rendezvous spec coverage](rendezvous.md).
- **Regenerate / verify.** Rows are maintained by hand against the pinned
  docs. To check that every referenced test and source file exists, run from
  the repository root:

  ```sh
  grep -oE 'crates/[a-z-]+/tests/[a-z_/]+\.rs::[a-z0-9_]+' docs/spec-coverage/quick-v2.md | sort -u |
    while IFS=: read -r file _ name; do
      grep -qE "fn ${name}\(" "${file}" || echo "missing ${file}::${name}"
    done
  grep -oE 'crates/[a-z-]+/src/[a-z_/]+\.rs' docs/spec-coverage/quick-v2.md | sort -u |
    while read -r file; do [ -f "${file}" ] || echo "missing ${file}"; done
  ```

  When the docs pin moves, diff the pinned sections
  (`git -C <docs> diff 27a794d <new> -- website/src/content/docs/ns/`)
  and update the affected rows and line ranges.

## Decisions

Spec questions resolved by the protocol owner (recorded in the code docs of
`lan.rs (v0.1.0)`, `region.rs (v0.1.0)` and `crates/nsshared-identity/src/record.rs`), plus one interpretation:

1. **lan6 layout (Q1).** `lan6(I, subnet_id) = fd ‖ BLAKE2s(out = 9, key =
   "ns-lan-addr-v2")(I ‖ subnet_id_be16) ‖ 0x0000 ‖ IPv4`, a `/96` prefix with
   the IPv4 address in the low 32 bits (ns/next.md §4.1 lines 75 and 83).
   `lan.rs (v0.1.0)::Lan6Prefix`.
2. **Region marks and bodies (Q2).** v2 MARKS is `[I, committed_gen,
   committed_K, conflicted, incarnation_high_water]`; the merge is the v1
   monotone rule without `revoked_through`. PRESENT, GONE and FORWARD use the
   v2 bodies of quick-v2 §8.5. `region::marks.rs (v0.1.0)::join_region_marks`.
3. **Region frame types (Q3, Y1, Y2).** Region frame `ver = 2`; types 1-9
   keep their numbers, channels and semantics. Types 10 RENDEZVOUS_REQUEST,
   11 RENDEZVOUS_RESPONSE and 12 REGISTRY_RECORD are control-connection only
   (Y2); their bodies live in `nsshared_proto::rendezvous::region` and `RegionFrame::decode`
   still refuses them as unknown types. Frames of types 10 and 11 on the
   control connection may reach 20480 bytes; every other frame, and every
   frame on the data connection, stays at 4096 bytes, checked from the length
   prefix before allocating (Y1). The v1 QUICK frames and the region quick
   owner decision are dropped. `region.rs (v0.1.0)` (extension point doc),
   `region::frame.rs (v0.1.0)::RegionFrameType`,
   `region::frame.rs (v0.1.0)::max_region_frame_bytes_for`.

   Decisions 2 and 3 are kept as a record; the code was removed on 2026-10-03
   (relay-internal) and is last in tag `v0.1.0`.
4. **Conflicting RECORD (interpretation).** An in-tunnel RECORD that hits a
   §3.3 conflict latch gets no ACK, like a lower generation (quick-v2 §9
   "rejected records get no ACK"). `control.rs (v0.1.0)::receive_record`.
5. **Service period (S1).** A NodeRecord with `expires - issued_at > 604800`
   is invalid (quick-v2 §3.2, bound from §3.1 and §12.3): `sign`, `decode` and
   `verify` reject it with `NodeRecordError::ServicePeriodTooLong`, after the
   canonical-shape checks and before the signature check.
   `crates/nsshared-identity/src/record.rs::NodeRecordError`.

## Node-control

The [Node-control specification](../spec/node-control.md)
fixes ACK minimum acceptance, unchanged v2 bytes and pure/runtime placement.
`crates/nsshared-control/src/node_control.rs` supplies constants, all five messages, exact error mapping,
unkeyed BLAKE2s-128 and greedy canonical endpoint selection.
`crates/nsshared-control/tests/node_control/codec.rs` preserves all ten tests from node source
`50f8e3fd95fac8bbc72aea9b132459103c3b206a`.
`crates/nsshared-control/tests/node_control/messages.rs::node_control_vectors` consumes independently
generated positives, known bytes, hash and malformed/boundary inputs. Runtime
ordering, durable ACK policy, peer authority and probe correlation remain
consumer responsibilities.
