# Provider-confirmed Exit contract, 0.9.0

This is the normative 0.9.0 installation-observation contract. It creates no forwarding authority. Names and field order below are normative.

## Encoding and bounds

All new codecs live in `nsshared_control::account::subnet`. Canonical CBOR uses definite arrays, minimal unsigned integers, exact byte lengths, UTF-8 text, no maps, unknown fields, tags, floats, indefinite lengths or trailing bytes. Arrays below list fields in wire order. Nested `bstr(Type)` contains that type's complete canonical encoding; NodeBinding and SubnetPrefix use their existing inline array codecs. The outer account byte bound is MAX_BYTES (existing 1 MiB); each encoded nested value is also bounded before allocation. New sets are strict ascending, duplicate-free and never normalized by decoders. Readiness publications hold at most 32 confirmations, ordered by `(selection_id, selection_generation)`, with at most one current confirmation per selection ID. One context names one committed selection/resource and its one current selected Exit grant, whose existing GrantDetails::Exit contains exactly one route. Multiple selections are scheduled as separate fair exchanges. This single-context choice avoids a new batch/partial-ACK protocol.

## Eight wire types

`Id16 = bstr(16)`, nonzero. `Digest32 = bstr(32)`. `WG32 = bstr(32)`, nonzero. All times are unsigned Unix milliseconds and exclusive deadlines. Positive counters must refuse overflow; tokens compare by equality only.

1. `ExitInstallationIncarnation(pub [u8;16])`: canonical scalar Id16. Consumer and provider fields are separate lifetime domains. NSD application incarnation and installation IDs also use Id16, without inventing additional wrappers.
2. `ExitInstallContext`:
   `[1, challenge_id:Id16, nsd_incarnation:Id16, receipt:bstr(RouteReceipt), consumer_node:NodeBinding, consumer_incarnation:ExitInstallationIncarnation, provider_source:bstr(SourceBinding), provider_node:NodeBinding, provider_incarnation:ExitInstallationIncarnation, grant:bstr(ServiceGrant), grant_version:u64>0, grant_publication_digest:Digest32, return_hosts:[bstr(16)], valid_until_unix_ms:u64>0]`.
   Consumer SourceBinding is the exact `receipt.command.binding.binding`; the signed binding is retained in the receipt, not duplicated. Receipt must be Selected, and its Select action provider/resource/typed selection must match the exact grant route. Both source scopes are `nodes`, same NSD/Network/profile; source recipient/source_node and corresponding NodeBinding.identity equal the endpoint identity. Consumer/source/grant/route recipient and provider identities must agree. Existing valid NodeBinding and nonzero grant incarnation are mandatory. `grant_version` and digest refer to the actual issued family-4 exit-grants PublicationEvent version/payload digest, not a recompiled prospective grant or a numeric log counter. Resource nsd_id/network_id match the embedded route publication and served Network. The full route includes mapped/real geometry, exclusions, bypasses and selection. Selected IPv4 coverage must be nonempty and mapping valid. `return_hosts` is exactly the single IPv6 host derived by the helper below, encoded without a prefix length because only /128 is permitted. The deadline cannot exceed the grant expiry. NSD bounds it additionally by all authority/source/control validity deadlines; wrapper refresh alone never extends it.
3. `ExitPeerReceipt`:
   `[1, installation_id:Id16, local_wg:WG32, consumer_wg:WG32, return_hosts:[bstr(16)]]`.
   Hosts are strictly sorted, exactly one for this context, and must equal context.return_hosts; keys equal context.provider_node.wg_key and context.consumer_node.wg_key respectively. Installation ID names continuous installed peer/effect custody, not a submission ticket. Exact /128 source ownership and collision refusal remain native owner obligations.
4. `ExitBindingReceipt`:
   `[1, generation:u64>0, resource:bstr(ServiceRef), real:SubnetPrefix, interface_index:u32>0, interface_name:text(1..256 bytes), source_ipv4:bstr(4), adopted_until_unix_ms:u64>0]`.
   Resource and real prefix equal the grant route. Source IPv4 is neither unspecified, multicast nor broadcast. Interface name is data text without control characters. Deadline is the expiry actually adopted by the live Entry/permission/accounting owners and must equal the context grant expiry; it is not inferred from NSD issuance or immutable Entry.grant. Native valid binding and live TCP/UDP/output/permission owners remain required.
5. `ExitInstallStatus`: `[0]` = NotInstalled; `[1, bstr(ExitPeerReceipt), bstr(ExitBindingReceipt)]` = Installed. No pending/reconciling state means uninstalled by itself.
6. `ExitInstallObservation`:
   `[1, challenge_id:Id16, context_digest:Digest32, provider_incarnation:ExitInstallationIncarnation, generation:u64>0, status:ExitInstallStatus]`.
   Correlation requires equality with the issued context ID/digest/provider incarnation, positive unexpired context and all Installed receipt fields above. NotInstalled is only effective for its exact issued/current context. Generation orders observations within `(NSD incarnation, provider incarnation, challenge ID)`; lower refuses, equal with identical canonical content is idempotent, equal with differing content conflicts. Exhaustion requires a new actual owner/context and fails closed; do not wrap counters.
7. `ExitProviderConfirmation`:
   `[1, context:bstr(ExitInstallContext), observation:bstr(ExitInstallObservation), valid_until_unix_ms:u64>0]`.
   Only Installed is allowed, fully validated for the context; confirmation expiry cannot exceed context or adopted grant deadlines. A consumer must establish role-specific currentness as specified below and check actual time, not just decode or self-compare this value. NSD creates this only after guarded acceptance of the exact observation.
8. `ExitReadinessPublication`:
   `[1, 4, nsd_id:bstr(16), network_id:bstr(16), recipient:Identity32, revision:u64>0, confirmations:[bstr(ExitProviderConfirmation)]]`.
   Every context's resource IDs/consumer source/identity must match this scope. One source/profile/consumer installation incarnation and NSD application incarnation per complete set. Complete empty set removes all confirmations in this key. It neither withdraws route authority nor changes selection/capture state.

The public API includes `canonical`/`decode` on context, peer, binding, observation, confirmation and publication; `digest` on context/observation; observation `validate_for(context, now_unix_ms)` and `validate_successor(previous)`; confirmation `validate_for(expected_context, now_unix_ms)`. Status is encoded only inside observation. Helpers establish structure/correlation, never authoritative currentness or native effect custody.

## Existing carrier extensions

`GatewayReport` changes to fixed 14-element schema 2:
`[2, request_id, software_version?, source_revision?, connections?, terminate_enabled?, public_http_port?, internal_http_port?, draining, capabilities, public_ingress_scopes, certificates, public_host?, exit_installation?:bstr(ExitInstallObservation)]`.
Previous field semantics/order remain; optional values use CBOR null. The former optional trailing public_host becomes a mandatory nullable slot. Old schema-1/12-or-13-element reports refuse. `exit_installation=None` reports health only and cannot clear a current confirmation.

`GatewayReportResponse` changes to:
`[2, request_id:bstr(16), accepted_exit_installation?:Digest32, exit_challenge?:bstr(ExitInstallContext)]`.
The accepted digest is the exact observation digest from this pending request, including status/generation/context. It is present only if NSD accepted that Exit part; a health receipt/request-ID echo alone is never an installation ACK. Unknown/stale Exit parts get no accepted digest and cannot erase an unrelated current confirmation. Codec correlation refuses an accepted digest when the request has no observation or a different observation. The next challenge may be identical to the retained current one; it supplies no authority and cannot retroactively be answered by the request obtaining it. Contexts are scheduled fairly, a new challenge is answered promptly through the existing reporter, and identical answered challenges do not form request loops. Wake the existing reporter on new challenges, installation changes and withdrawals; include the Exit observation ID/digest/generation/content in change detection so health telemetry coalescing cannot suppress it. Retain live guards through request preparation, write and ACK acceptance; known invalidation retires local eligibility immediately. No packet retries or shorter readiness timer is introduced. FencedGatewayReportRequest/Response keep their existing outer membership/runtime tuples and validate the extended nested values; response canonical now returns Result.

`PublicationSubscriptionRequest` becomes fixed nine-element schema 1: append `exit_installation:Option<ExitInstallationIncarnation>` after `service_control`. Mandatory slot is null for nonparticipants; Some is required by consumer/gateway readiness admission. Old eight-element form refuses. Mint consumer token per real AuthenticationSession owner; mint provider token per engine/admission-owner lifetime, including replacement without a process restart. Keep boot_nonce/attempt_counter, service-control runtime fences and current signed SourceBinding checks independently. Subscriber declaration alone registers no authority; NSD must join admitted current source/Node/owner and refuse conflicting registrations.

## Snapshot and source validation

Publication key is **family 4, kind `exit-readiness`, channel Snapshot (1), scope `nodes`**, under the exact issuer/recipient/served Network. No numeric kind ID exists in this registry; number 4 is the family. Replacement rule clears `confirmations` only. Register no new family, method or provider publication. Extend the owning payload decoder and a dedicated readiness-context validator; do not route through grant/routing authority inputs. Signed SourcePublication plus current source/delivery matching, channel, membership IDs, issuer/recipient, payload revision/event version and exact consumer source are mandatory, including empty carrier withdrawal. Nonempty payloads must have all confirmations in the signed source scope. Authenticated FetchFailed uses a nonempty canonical ExitReadinessPublication with zero confirmations and the event revision; positive failure payloads refuse. It clears to unavailable; no cached positive survives cold capture after application restart. Missing/unknown capability cannot open the traffic gate.

## Hashes and return identity

`ServiceGrant::canonical()` validates its inferred existing family and emits exactly the existing seven-element grant record, not an enclosing publication. `ServiceGrant::decode` decodes that exact record. `ServiceGrant::digest()` = SHA-256(`b"ns-exit-grant-v1\0" || canonical_grant`). It includes expiry, incarnation, payer and full route publication. NSD must compare this value at acceptance; grant-publication provenance remains separately recorded as SHA-256 of the exact canonical GrantPublication payload. Keep original issuance provenance when an unrelated collection revision changes while the selected canonical grant and live fences stay equal; it is not a requirement to match an incidental current wrapper version. No per-grant version is invented.

`ExitInstallContext::digest()` = SHA-256(`b"ns-exit-context-v1\0" || canonical_context`). There is no self-referential digest field in the context. `ExitInstallObservation::digest()` = SHA-256(`b"ns-exit-observation-v1\0" || canonical_observation`). Domains include their terminating zero byte. No additional framing or normalization occurs.

`consumer_return_identity(identity:&[u8;32], mapped:SubnetPrefix) -> Result<Ipv6Addr,AccountError>` preserves the existing v1 mapping and ns-alias4-v2 derivation. Validate aligned IPv6 fd ULA mapped prefix /96..128 with subnet bytes[6..8]=00 01. For indices 0..15, compute **keyed BLAKE2s with digest_size=3, key=b"ns-alias4-v2", message=identity || [4,index]**; interpret its three bytes big-endian, shift right 2, reduce modulo 2^21 and OR with 100.64.0.0. Take the first address unequal to 100.64.0.1 (existing gateway rule); bounded exhaustion refuses. Replace mapping bytes[6..8] with 00 02, zero bytes[8..12], and set bytes[12..16] to that IPv4 alias. Output is an IPv6 host used only as /128. This is lossy: current membership collision detection must reject every conflicting ownership; helper output alone never authorizes installation. No new hash domain is introduced for this existing derivation.

Independent Python vectors in `account/subnet/readiness` cover all hashes, complete context/receipts/confirmation/publication, both selection kinds, empty replacement and negative codecs. Literal vector outputs are frozen in the checked-in fixture and copied into the vector appendix below before PR delivery.

## Currentness and invalidation obligations

### Role-specific expected facts

| Role | Independently held inputs | Facts learned from the authenticated exchange |
| --- | --- | --- |
| NSD | Retained issued challenge and application incarnation; coherent current selection/receipt, issued grant/provenance, both source/Node registrations and installation-owner tokens, authority deadlines and observation-generation floor. Recheck them under the current Network/registration guards at acceptance and delivery. | Gateway native peer/binding evidence and adopted deadline are observations to compare against that expectation, never a source of expected authority. |
| nsgw | Current accepted provider source/Node/engine token, admitted grant publication and exact grant, independently derived return hosts, both live native installation owners and actual adopted deadline. | Challenge ID, NSD application incarnation, committed consumer receipt and consumer authentication incarnation arrive in the authenticated NSD challenge. Match its grant/route/endpoint facts against admitted authority; the challenge does not grant permission. |
| ns client | Current authorized NSD/Network/nodes source and delivery; its own source/Node/authentication incarnation; the complete committed receipt including selection ID/generation, request and provider/resource/typed selection; current authorized real/mapped route geometry, exclusions/bypasses and independently derived return host; clock and current control freshness. Check the same owner/selection before and after projection. | Challenge ID, NSD application incarnation, provider source/Node/installation incarnation, exact provider grant and issuance provenance, native installation evidence/report generation and bounded confirmation deadline are NSD attestations after current signed source/delivery and membership acceptance. They are not a separately available client challenge/registration/grant stream. Cross-check independently held current facts for contradictions, but do not wait for a provider exit-grants subscription the client does not have. |

`ExitProviderConfirmation::validate_for` compares the entire supplied expected context and time. NSD can supply its retained issued context; nsgw can supply its authenticated challenge after the independent admission/native checks above. A client first validates the NSD attestation and compares **all** its independent local facts; remote-only slots may then come from that validated attestation when assembling an expected context for the helper. Cloning a received context and calling `validate_for` establishes only self-consistency/expiry, **not** independent local currentness, source/delivery authenticity or native custody. No additional discovery channel or wire field is required.

- NSD retains challenge/report/registration/generation custody in memory for its application lifetime, with a fresh NSD incarnation on restart. No table/migration. Re-capture existing persistent selection, issued grant and sources under the Network write fence at acceptance and publication; compare all fields with the retained challenge, never learn expected facts from reports. Cold capture overwrites retained signed positives with the current initially empty set before delivery. Delivery rechecks eligibility. Authenticated health acceptance is separate from Exit acceptance.
- New selection generation, same-action reselect, source/Node/WG replacement, consumer owner/reset/reconnect, provider engine/admission-owner replacement, NSD restart, changed canonical grant including expiry renewal, withdrawal/clear/floor loss/expiry invalidate the old challenge/proof. Renewal requires actual Entry/permission/accounting deadline adoption. Delayed positive or negative cannot cross those fences. Registration drop/replacement revokes only the exact old owner; conflict yields no confirmation.
- Gateway joins matching completed applied peer/readback/accounting receipt and live Exit binding/Entry/output/permission receipts, retaining guards through report write/response acceptance. Exact local/consumer WG keys, /128 routes, resource/route and adopted deadline must match. Prepared peers, Node L3 Applied, diagnostic generation, broad prefixes, peer counts and successful traffic are insufficient.
- Genuine no-op local reconciliation never alters provider proof/intent/incarnations. Healthy no-op gateway reapplication preserves continuous installation ID/binding generation/guards, and is classified before destructive deny/restage. A new ticket/progress callback alone does not emit NotInstalled. Old AppliedCoverage alone is insufficient after failure. Real teardown, cancellation, uncertainty or authority/effect loss invalidates immediately, even if final values later match; no debounce or last-good latch.
- Client retains a typed source-owned observation outside CandidateView/capture/grant authority, rechecks current owner/selection before and after projection, and evaluates provider independently of PathApplication.applied/receipt-map/installer. Missing authority/freshness yields unavailable; current authority without exact live proof yields not_confirmed; exact current proof yields confirmed. Local applied remains truthful, including the separately owned receipt-only issue. That repair is parallel, not a prerequisite for provider-only stability; combined continuous-stability claims require it.

## Dedicated ns query contract

CLI `ns exit status --json` uses api_version 6. Dedicated private operation `exit_provider_status_v1` and additive FFI `ns_engine_exit_provider_status_json_v1` return api_version 1 with the same fields and meaning. FFI signature is `char *ns_engine_exit_provider_status_json_v1(struct NsEngineHandle *handle, const char *request_json_utf8)`; strict request JSON is `{api_version:1, network:string|null}` with the existing membership selector semantics (omitted network is equivalent to null). Returned strings use `ns_string_free`, failures return null and set last error; ABI remains 5. Capability is `exit-provider-status-v1`. Existing status/info, config/candidates/select/clear products and symbols remain unchanged. Select success means command commitment; traffic readers explicitly poll the new query.

The private operation uses the existing instance-bound local-control framing with new seven-byte opcode `b"exrget\n"`. Its strict request is `{profile_id:string, instance_id:string, membership:string, operation:{operation:"exit_provider_status_v1"}}`; the runtime must compare both profile and instance before resolving the exact membership. Reply is `{status:CombinedReadinessV1|null, error:string|null}`, with exactly one non-null. Success status contains the fields below with api_version 1. Transport/framing bounds stay the existing private-control bounds. Neither aggregate status nor the existing NodeRoute status response is extended.

Exact output keys (strict, all required):
`{api_version, node_route, path_readiness, default_available, provider_readiness, provider_confirmation}`.
`node_route` is the unchanged existing NodeRouteStatus v1 object, including actual Default discriminator and selection/receipt/generation. `path_readiness` is unchanged `applied|not_applied`; `default_available` is the actual boolean. `provider_readiness` is `unavailable|not_confirmed|confirmed`. `provider_confirmation` is null unless confirmed, otherwise a strict object:
`{selection_id:lowercase_hex_16_bytes, selection_generation:u64, provider:lowercase_hex_32_bytes, provider_incarnation:lowercase_hex_16_bytes, report_generation:u64, valid_until_unix_ms:u64}`.
All summary fields derive from the same current accepted proof. Do not expose raw reports, capabilities or host diagnostics. A first-traffic gate requires current command Committed, local applied and provider confirmed for the exact requested selection/generation in one coherent query; no fallback or quiet window. Later receipt-only Pending neither withdraws remote proof nor reconnects/reselects established traffic.

Rust storage detail: `ExitInstallStatus::Installed.binding` is `Box<ExitBindingReceipt>` to avoid a large enum; the wire encoding above is unchanged.
